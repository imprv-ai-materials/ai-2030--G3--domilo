# B1. Wersja v3_przedzialy: wycena z przedziałem albo „nie wiem”, i koszt odmów

Źródło: `domilo.duckdb` zbudowana z `data/` (eksport 2026-09-30 23:59 Europe/Warsaw) przez `pypyr baza`.
Policzono 2026-11-15. Liczby z danych pochodzą z
[`ewaluacja_v3.py`](../api/api/ai/valuation_model/evals/ewaluacja_v3.py) (sekcja [SQL i kod](#sql-i-kod)) i są
zapisane w `api/api/ai/valuation_model/versions/v3_przedzialy/metryki.json`. Stałe kosztowe i warunki banku to
**założenia od użytkownika** z [`valuation_bc/zalozenia.yaml`](../api/api/contexts_boundaries/valuation_bc/zalozenia.yaml).

## Wnioski

Nowa wersja modelu dla każdego lokalu podaje wycenę z przedziałem 80% albo odmawia i pisze słowami dlaczego.
Na transakcjach z 2026 odmawia w 5,6% przypadków, a dla przyjętych przedział obejmuje 77,9% cen, czyli mieści się w
normie banku 77–83%. Średni błąd 8,50% jest jednak wciąż powyżej wymaganych 8%. Przy corocznej wycenie 7 200 lokali
Domilo proponowany próg odmowy daje 569 wycen wewnętrznych rocznie, czyli 85 350 zł przy 150 zł za wycenę. Same
operaty roczne kosztowałyby 3 240 000 zł (7 200 × 450 zł). Wariant, który dodatkowo odmawia przy zbyt szerokim
przedziale, schodzi do błędu 7,65% przy pokryciu 77,0%, na samej granicy normy. Daje 936 wycen wewnętrznych za
140 400 zł rocznie. Żadnej z tych wersji nie sprawdziliśmy jeszcze na 300 operatach kontrolnych banku, a przy
żadnej liczbie w założeniach nie wpisano jeszcze osoby odpowiedzialnej.

Jak czytać:

- 410 z 569 odmów to dwa budynki w dzielnicach z małą liczbą transakcji RCN. Te odmowy wrócą w każdym roku, dopóki
  w rejestrze nie przybędzie transakcji z tych dzielnic albo nie zmienimy reguły. Liczba odmów jest więc w dużej
  części stała, a nie losowa.
- Między progami 0,99 a 0,999 koszt różni się o 4 800 zł (32 wyceny). Próg 0,95 kosztuje o 64 350 zł więcej i odrzuca
  zwykłe lokale (b1_ood.md, tabela 4).
- Nie sumujemy kosztu wycen wewnętrznych z próbką kontrolną, bo nie znamy częstotliwości próbki (w danych jedna,
  wrzesień 2026). Nie liczymy też oszczędności: wymaga to zgody banku na zastąpienie operatów rocznych modelem, a
  model nie przeszedł jeszcze sprawdzianu na operatach kontrolnych.

## Co jest w wersji

| Element | Plik | Opis |
|---|---|---|
| klasa | `versions/v3_przedzialy/model.py`, `ModelWycenyV3` | P50 + P10/P90 z `ModelPrzedzialuCQR`, odmowa z `DetektorOOD`; `max_szerokosc` (domyślnie `None`) włącza wariant B |

## SQL i kod

Odtworzenie (z katalogu głównego repozytorium):

```bash
pypyr baza
cd api && poetry run python -m api.ai.valuation_model.evals.ood_v3                  # detektor (jeśli nie ma ood.joblib)
poetry run python -m api.ai.valuation_model.evals.ewaluacja_v3 --od-zera            # tabele 1–3, zapis v3
cd .. && pypyr test tests="api/tests/test_wycena_v3.py api/tests/test_valuation_zalozenia.py"
```

Wolumen roczny:

```sql
SELECT year(data_wyceny) AS rok, min(data_wyceny), max(data_wyceny), count(*) AS operaty,
       count(DISTINCT id_lokalu) AS lokale
FROM operaty WHERE typ = 'roczny' GROUP BY ALL ORDER BY rok;   -- 2025: 7 200
SELECT count(*) FROM pms_lokale;                                 -- 7 200
```

Lokale Domilo i oferty z cechami: jak w b1_ood.md (`wczytaj_lokale_domilo`, `wczytaj_oferty`).

```python
zal = wczytaj_zalozenia()                                    # valuation_bc/zalozenia.yaml
v3 = ModelWycenyV3(przedzial=<v2_lgbm_geo_cqr/model.joblib>, detektor=<v3_przedzialy/ood.joblib>)
v3b = ModelWycenyV3(..., max_szerokosc=prog_szerokosci(v3, walidacja))   # 0,3426
p = v3.predict_interval(d)                                   # p10, p50, p90, odmowa, powod
przyjete = ~p.odmowa
mape = 100 * mean(|p50 − y| / y)[przyjete];  pokrycie = 100 * mean(p10 <= y <= p90)[przyjete]
# koszt: dla progu q (kwantyl wyników treningu kNN / IF) i wariantu
odmowy = ModelWycenyV3(..., prog_knn=q_knn, prog_if=q_if, max_szerokosc=...).predict_interval(domilo).odmowa.sum()
wyceny_wewnetrzne_rocznie = odmowy / 7200 * wolumen          # wolumen = 7 200 (operaty roczne 2025)
koszt = wyceny_wewnetrzne_rocznie * zal["koszt_wyceny_wewnetrznej_pln"]["wartosc"]       # 150 zł
odniesienie = wolumen * zal["koszt_operatu_pln"]["wartosc"]                             # 450 zł
```
